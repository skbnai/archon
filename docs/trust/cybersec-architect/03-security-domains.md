A reference guide to all major enterprise security domains — identity, cloud, network, endpoint, application, data, infrastructure, and security operations — with the technology, tools, and architecture patterns for each.

## Identity Domain

Identity is the primary control plane for modern enterprise security: every access decision starts with who is this, what are they allowed to do, and in what context. IAM spans directory services (canonical identity store — Entra ID, Okta, Google Workspace, AD DS), authentication (FIDO2/passkeys, MFA, SSO), authorization (RBAC, ABAC, ReBAC via the Google Zanzibar model), identity governance (lifecycle management and access reviews — SailPoint, Saviynt, Microsoft IGA), and federation (SAML 2.0, OIDC, WS-Federation).

Privileged accounts are the primary target once an attacker has initial access. PAM's core capabilities: credential vaulting (secrets checked out per session, never stored on endpoints); session recording (full keylog and video of privileged sessions); just-in-time access (privileges granted only when needed, for the minimum duration); just-enough-access (roles constrained to specific commands, not full admin); and privileged access workstations (hardened, dedicated devices for admin tasks). AI agents requiring administrative access must use PAM-integrated credential vaulting — never hardcoded keys in prompts or environment variables.

Federation protocols serve distinct purposes: SAML 2.0 for web SSO and enterprise applications (SP-initiated and IdP-initiated flows); OAuth 2.1 for API authorization and agent delegation (Auth Code plus PKCE, Client Credentials); OIDC as the identity layer on top of OAuth (ID Token, UserInfo endpoint); and SPIFFE/SPIRE for workload identity in Kubernetes/service mesh environments (SVIDs via X.509 or JWT). As of 2026, machine identities outnumber human identities roughly 10:1 in the average enterprise, requiring certificate lifecycle automation (ACME, Venafi, cert-manager), a secrets manager (Vault, AWS Secrets Manager, Azure Key Vault), dynamic short-lived credentials generated per workload, workload identity federation (cloud IAM roles for service accounts via OIDC), and a dedicated agent identity layer (IETF AIMS, Entra Agent ID, AWS AgentCore identity — detailed in [Part 6](06-identity-architecture.md)).

## Cloud Security Domain

CSPM continuously assesses cloud configurations against security benchmarks: multi-cloud visibility (AWS, Azure, GCP, OCI), misconfiguration detection (public buckets, overly permissive IAM, unencrypted storage), compliance posture against CIS/NIST/PCI DSS/HIPAA, drift detection with remediation automation, and business-context risk prioritization — led by Wiz, Orca, Prisma Cloud, Defender for Cloud, and Lacework. CWPP protects workloads at runtime: vulnerability assessment of running workloads, runtime threat detection (process/network/filesystem anomalies), container image scanning and policy enforcement, serverless function monitoring, and memory protection against exploits. CIEM addresses the identity-permission explosion — the average cloud environment carries 10,000+ identities with excessive permissions, which attackers exploit to escalate privilege — via discovery of all cloud identities (human, machine, service), permission baselining (used versus granted), over-permission detection with right-sizing recommendations, and cross-cloud entitlement visibility. CNAPP consolidates all three plus IaC scanning into one platform: point solutions produce disconnected alerts, while CNAPP correlates misconfigurations, running vulnerabilities, and excessive permissions into prioritized attack paths, dramatically reducing alert fatigue — Wiz is the 2026 market leader, alongside Orca, Prisma Cloud, and Defender for Cloud.

## Network Security Domain

Segmentation approaches range from VLAN segmentation (L2 isolation, legacy on-prem) through firewall zones (L3/L4 policy, DMZ/prod-dev isolation) to microsegmentation (L7 workload-to-workload policy, Zero Trust for data centers and cloud) and private connectivity (VPC peering, Private Link, Direct Connect). ZTNA replaces VPN with identity-aware, application-specific access: a verified-posture device connects through a ZTNA client, which carries identity and device signals to a cloud policy-evaluation service, which brokers access through an in-network application connector to the specific target application — never granting network-level access, only application-level, with device posture enforced at access time and no lateral movement risk since the user never gets actual network access. SASE converges networking and security into a cloud-delivered service: SD-WAN (optimized, policy-driven routing) plus SSE, where SSE itself combines CASB (SaaS control), SWG (web filtering), ZTNA (identity-aware access), and optionally FWaaS and inline DLP — led by Zscaler, Palo Alto Prisma, Netskope, Cato Networks, and Cisco+.

## Endpoint Security Domain

EDR provides continuous endpoint monitoring: process/network/filesystem/registry event collection, behavioral detection (anomaly plus threat intel plus ML), automated response (process kill, network isolation, file quarantine), a threat-hunting query interface, and forensic investigation support — led by CrowdStrike Falcon, Defender for Endpoint, SentinelOne, and Carbon Black. XDR extends EDR by unifying endpoint, network, cloud, identity, and email telemetry into a single detection platform, enabling cross-source correlation that catches attacks spanning multiple surfaces invisible to any point solution — led by Microsoft Sentinel plus Defender XDR, CrowdStrike Falcon Complete, and Cortex XDR. MDR is a managed service providing 24/7 monitoring using the customer's own EDR/XDR telemetry, handling triage/investigation/guided response while escalating containment decisions to the customer team — appropriate for organizations without 24/7 SOC staff or wanting to augment an existing one. MDM enforces mobile device policy: enrollment (corporate versus BYOD), configuration enforcement (VPN, certificates, email profiles), app management, compliance monitoring for Zero Trust integration, and remote wipe on loss or departure — led by Intune, Jamf, and VMware Workspace ONE.

## Application Security Domain

SAST analyzes source code at build time without execution — catching injection flaws, hardcoded secrets, insecure dependencies, and logic errors — integrated as IDE plugins plus a CI pipeline gate blocking on high/critical findings (Semgrep, Checkmarx, Veracode, Fortify, GitHub Advanced Security). DAST tests running applications by simulating attacks — catching authentication flaws, injection vulnerabilities, CORS misconfigurations, and API exposure — gating pre-production release (Burp Suite Enterprise, OWASP ZAP, Invicti, StackHawk). IAST instruments the running application from the inside during functional QA, combining SAST's speed with DAST's accuracy at a low false-positive rate, with no separate security test phase required. RASP embeds in the application runtime to detect and block attacks in production by inspecting function calls, database queries, and file operations in real time — blocking exploits without a patch or WAF rule update, particularly valuable for legacy applications that can't be patched quickly. API security follows the framework in [Part 2](02-enterprise-security-architecture.md), with every MCP server and agentic tool endpoint treated as an API requiring the same authentication/authorization/rate-limiting/input-validation/logging controls applied to customer-facing APIs.

## Data Security Domain

DSPM discovers, classifies, and monitors data across cloud environments: sensitive data discovery (PII, PCI, PHI) across structured and unstructured stores, data-flow mapping to identify unexpected access or movement, misconfiguration identification (public buckets, unencrypted sensitive data), and a data risk inventory for compliance/privacy programs (Cyera, Varonis, BigID, Securiti, Microsoft Purview). DLP prevents sensitive data leaving through unauthorized channels — email (scanning outbound attachments and body), web browser (blocking uploads to personal sites), removable media (blocking or encrypting USB copies), cloud storage (CASB monitoring of personal cloud sync), generative AI (blocking sensitive submissions to public LLMs), and agent outputs (filtering agent responses before user delivery). Users pasting sensitive documents into ChatGPT or Claude.ai is the dominant enterprise DLP incident as of 2026, controlled via CASB policy blocking classified-data submission to AI services and routing all AI access through a corporate AI gateway as the sole approved path.

Encryption spans four states: at rest (AES-256 for databases/filesystems/object storage, managed via cloud KMS); in transit (TLS 1.3 for all communications, with automated certificate lifecycle management); in use (confidential computing via Intel TDX/AMD SEV, hardware-backed TEE); and field-level (AES-256 or format-preserving encryption via application-layer KMS integration). Tokenization replaces sensitive values with tokens carrying no mathematical relationship to the original — format-preserving tokenization keeps the original format for legacy system compatibility, vaultless tokenization derives tokens via a keyed cryptographic function with no central database, and the primary use case is PCI DSS scope reduction, since systems processing only tokens fall outside PCI scope. Data masking creates realistic but fictitious data for non-production use — static masking for pre-production copies, dynamic masking applied at query time based on user role, and AI training-data masking removing PII before inclusion in training datasets.

## Infrastructure Security Domain

Beyond CSPM, CWPP, and CIEM (covered above under Cloud Security), CNAPP's consolidated view spans the full lifecycle: code (SAST, SCA, secret scanning), build (IaC scan, image scan), deploy (CSPM, config drift detection), and runtime (CWPP, EDR, runtime threat detection). A representative correlation example shows why this matters: CSPM finds an S3 bucket with a public read policy; CIEM finds a Lambda function holding `s3:GetObject` on that bucket via an over-broad role; CWPP finds a known CVE in the Lambda's runtime library — individually three low-to-medium findings, but CNAPP correlates them into a single critical attack path (external attacker → public bucket → Lambda exploit → data exfiltration) that no point solution would have prioritized correctly in isolation.

## Security Operations Domain

SIEM aggregates and correlates security events enterprise-wide: log ingestion from endpoints/firewalls/identity providers/cloud services/applications; normalization to a common schema (ECS, OCSF); rule-based and ML correlation; prioritized alerting routed to analyst queues or SOAR; and long-term retention for forensics and compliance (Microsoft Sentinel, Splunk, IBM QRadar, Google Chronicle, Elastic SIEM) — AI enhances this with LLM-assisted alert triage, natural-language telemetry queries, and automated alert summarization. SOAR automates repetitive operations: structured playbooks for common incident types, API connectors to 200+ security tools, case management (investigation tracking, evidence collection, stakeholder communication), and MTTD/MTTR/analyst-capacity metrics (Palo Alto XSOAR, Splunk SOAR, Sentinel Automation, Torq, Tines).

Threat intelligence spans four horizons: strategic (months to years — nation-state sector targeting, consumed by the CISO and Board), operational (weeks to months — a campaign targeting financial firms with spearphishing, consumed by the SOC Manager), tactical (days to weeks — a specific malware family's TTPs, consumed by the SOC analyst), and technical (hours to days — IOCs like IPs/domains/hashes, consumed directly by SIEM/SOAR). Sources include MITRE ATT&CK, ISAC feeds, commercial intel (Recorded Future, Mandiant, CrowdStrike Intel), and open-source feeds (AlienVault OTX, MISP) — MITRE ATLAS specifically tracks AI-adversarial TTPs and is the primary source for AI threat intelligence, mapped fully in [Part 8](08-ai-governance.md).

Security analytics applies statistical and ML techniques: UEBA baselines normal behavior and alerts on deviation; Network Traffic Analysis detects C2 communications, exfiltration, and lateral movement in flow data; threat hunting is analyst-driven proactive search for what detection rules miss; and Breach and Attack Simulation continuously tests detection coverage. Domain-level investment priorities for 2026 run Very High for Identity (credential theft, privilege abuse) and Cloud (misconfiguration, exposed data); High for Network (lateral movement, exfiltration), Endpoint (malware, ransomware), Application (injection, API abuse), Data (exfiltration, privacy breach), and Infrastructure (misconfiguration, supply chain); and Medium-High for Operations (alert fatigue, slow response).
