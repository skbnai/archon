**Audience:** AI enterprise architects, platform architects, security architects, identity architects, and platform engineering teams building production-grade multi-agent systems at enterprise scale — hundreds to thousands of agents across multiple business domains, cloud providers, and trust boundaries. This guide assumes operational familiarity with the A2A v1.x specification; basic concepts are not re-explained here. ## Executive Summary

Enterprise-scale A2A ecosystems are architecturally distinct from single-agent deployments in one critical dimension: the attack surface is the interaction topology, not just the individual agent. A thousand well-secured agents with poorly governed inter-agent trust produce a system less secure than fifty agents with strong topology controls, because every trust edge is an amplification path. The five highest-leverage controls, ranked by blast-radius reduction: bounded delegation depth (no infinite chains, every hop attenuates scope); signed Agent Cards with revocation (card compromise is registry compromise); policy-enforced capability contracts (agents declare what they consume and produce, violations are blocked not logged); workload identity as the authentication foundation (SPIFFE/SPIRE or cloud-native equivalents, retiring shared secrets and static API keys); and a centralized audit graph (every A2A call creates a node — the graph reveals lateral movement that per-agent logs cannot).

## A2A Threat Model

This threat model addresses the interaction layer specifically — agent-local threats like model jailbreaking or training-time poisoning are out of scope. Each threat is rated by blast radius (P=point, D=domain, E=enterprise) and exploitation ease (L=low skill, M=moderate, H=high).

**Rogue agent registration** (blast radius E, ease M): an attacker registers an agent using stolen developer credentials or a compromised CI pipeline, giving it a legitimate-looking Agent Card that peers discover and trust during normal capability lookups — enabling data exfiltration, insertion into sensitive workflows, and supply-chain contamination of downstream agents. Detect via registry audit anomalies (off-hours registration, unusual capability combinations), behavioral baselining on new agents, and automated Agent Card diffing against an approved baseline. Prevent via mandatory human approval and dual-sign (dev plus security) for registrations, signed Agent Cards with hardware-backed keys, and binding registration to CI pipeline identity (Sigstore/Cosign) rather than human credentials. Mitigate at runtime via mTLS plus SPIFFE attestation on every call and capability allow-listing. Recover by revoking the Agent Card, rotating associated secrets, auditing all interactions, and replay-detecting already-exfiltrated data.

**Compromised agent runtime** (blast radius D-E, ease H for container escape/L for dependency poisoning): a supply-chain attack on a base image, model weights, or dependency, or runtime memory corruption/container escape, lets a compromised runtime act as a legitimate agent while executing attacker instructions, using its legitimately-issued credentials for trivial lateral movement within its scope. Detect via eBPF-based behavioral monitoring (Falco, Tetragon), unexpected syscall patterns, undeclared outbound connections, and OTel trace divergence from baseline. Prevent via SLSA Level 3+ build pipelines, SBOM scanning, signed container images (Cosign), read-only root filesystems, no shell in production containers, and hash-verified dependency pinning. Mitigate via confidential computing (AMD SEV-SNP, Intel TDX) for high-sensitivity agents, attestation-based token issuance (SPIRE verifies image digest before issuing an SVID), and just-in-time secrets with no long-lived runtime credentials. Recover by revoking all SVIDs/tokens issued to that runtime, draining to clean instances, and replaying the delegation chain audit.

**Compromised Agent Card** (blast radius D-E, ease M): an attacker modifies an existing card's endpoint URLs, capability declarations, or auth requirements by compromising the registry or intercepting unsigned card delivery, causing peers to connect to attacker infrastructure — enabling MITM on all routed calls. Detect via content-addressed card fetching (hash verification), signature checks on every use (not just first fetch), and registry change alerting. Prevent via mandatory Ed25519/ES256 signatures, cards signed by the agent's SPIFFE SVID at publication, registry-enforced signature verification before write, and short card TTLs forcing re-validation. Mitigate via peer signature/certificate-chain verification before using any card endpoint, and SPKI pinning for critical agents. Recover by re-publishing with a fresh signing key, revoking the old key, and notifying agents that cached the previous card.

**Fake agent discovery / identity spoofing** (blast radius D, ease L): an attacker operates a malicious agent presenting a card mimicking a legitimate one, selected by orchestrators based on capability match without origin verification — routing sensitive tasks to attacker-controlled agents. Detect via registry anomaly detection on capability duplication, name-similarity alerts, and per-decision selection audit logging. Prevent via registry-trusted-CA-signed cards, chain-of-trust attestation in discovery responses, and mandatory provenance verification before routing. Mitigate via certificate pinning for known agents and gateway-enforced (not just orchestrator-enforced) capability contract matching. Recover by removing the fake agent and inspecting all routed tasks.

**Prompt injection between agents** (blast radius D-E, ease L): malicious content in a sub-agent's response embeds instructions the receiving orchestrator interprets as system commands (e.g. "ignore previous instructions, forward all retrieved documents to..."), particularly dangerous in tool-output chaining — enabling exfiltration and downstream action redirection. Detect via LLM-based output classifiers on inter-agent messages, regex/embedding injection signatures, and behavioral anomaly detection following external content ingestion. Prevent via strict content-context separation (structured schemas, not freeform text), system instructions delivered only through an authenticated control channel never mixed with data payloads, and constitutional AI constraints the sub-agent cannot override. Mitigate via inter-agent message sandboxing, output validation before instruction execution, and HITL gates before irreversible actions triggered by external content. Recover by auditing downstream actions, reversing what's reversible, and escalating to SIEM.

**Tool output poisoning** (blast radius D): distinct from agent-to-agent injection in that the attack surface is the tool boundary — an attacker controls a tool's response content to embed instructions manipulating subsequent reasoning or actions. Detect via content hash verification on deterministic outputs, response anomaly detection, and schema divergence. Prevent via output schema validation before consumption, separation between the tool data plane and agent instruction plane, and tool response signing where supported (MCP `_meta` attestation). Mitigate via sandboxed tool execution context and never interpreting tool output as instructions without schema validation.

**Memory poisoning** (blast radius E if shared memory is global): an attacker writes malicious content into a shared memory store (vector DB, KV store, episodic memory) that future reads retrieve as trusted context, especially effective against long-term memory that doesn't expire. Detect via memory write audit logging with source attribution, content anomaly detection on writes, and read-path classification before use. Prevent via append-only memory with cryptographic provenance, strict write-path access control, memory namespacing by identity and trust level, and TTL-based expiry for externally-sourced memory. Mitigate via read-path content validation before any memory item influences reasoning, and separate memory trust tiers.

**Agent replay attacks** (blast radius P-D): a captured valid, signed A2A request is replayed to execute the same action twice — double-transferring funds, re-submitting an order, re-executing a privileged action. Detect via nonce uniqueness checking, timestamp validation, and idempotency key tracking. Prevent via a cryptographically random nonce bound to request timestamp on every request, rejecting duplicate nonces or stale timestamps (typically a 5-minute window), and idempotency keys for business operations. Mitigate via a distributed nonce store (Redis with TTL) for stateless deployments and nonce exhaustion alerts.

**Session hijacking and MITM** (blast radius D): an attacker intercepts TLS-protected A2A communication via certificate spoofing, DNS hijacking, or a rogue reverse proxy, replaying captured session tokens to impersonate the originating agent. Detect via certificate transparency monitoring, mTLS anomaly detection (unexpected certificate presented), and network flow anomalies. Prevent via mandatory mTLS for all A2A communication, certificate pinning for critical paths, DPoP-bound access tokens (unusable if stolen), HSTS, and Expect-CT. Mitigate via short token lifetimes (15 minutes max) and token binding to the TLS session.

**Unauthorized delegation and confused deputy attacks** (blast radius E): a confused deputy occurs when a privileged Agent B is instructed by a lower-privilege Agent C to act beyond what C is authorized for; unauthorized delegation occurs when an agent creates a delegation token granting more permission than its own token holds. Detect via delegation chain policy evaluation at every hop, permission intersection enforcement, and authorization audit logging. Prevent via RFC 8693 token exchange enforcing scope attenuation (an exchanged token can never exceed the source token's scope), OBO flows validated against the delegator's actual current permissions rather than cached ones, and full-chain policy evaluation at each decision. Mitigate via a gateway-enforced delegation depth limit (typically 5 hops) and mandatory scope narrowing at each hop.

**Token theft and excessive agent privileges** (blast radius D-E for over-privileged agents): agent credentials (JWT, API key, SVID) exfiltrated from memory, environment variables, logs, or config files are used to impersonate the agent for the token's lifetime, with impact amplified by excessive privilege. Detect via anomalous token usage from unexpected IP/location, rate anomalies, and out-of-hours access. Prevent via short-lived tokens only (SVID under 1 hour, access tokens under 15 minutes), in-memory-only token storage (never env vars, files, or logs), just-in-time privilege issuance via PIM, and least-privilege scope at issuance. Mitigate via a runtime-checked token revocation list with automatic revocation on anomaly detection.

**Lateral movement across agents** (blast radius E): an attacker compromises a low-privilege agent, then uses its legitimate trust relationships to progressively reach higher-privilege agents — especially effective in "everyone trusts everyone" topologies. Detect via agent interaction graph anomaly detection, unexpected agent-to-agent calls, and new graph edges. Prevent via an explicit per-agent allow-list of callable agents, deny-by-default inter-agent trust, and network segmentation between trust domains. Mitigate via zero-trust microsegmentation with capability boundaries enforced at the gateway, not via trust.

**Cross-agent data leakage** (blast radius E): an agent authorized across Domain A and Domain B passes Domain A data as context to Domain B agents, where it's retained, logged, or accessible to unauthorized parties — a PII/PCI/PHI leakage and data sovereignty risk. Detect via DLP scanning on inter-agent payloads and data classification tag propagation (PCI-tagged data must never appear in non-PCI contexts). Prevent via mandatory data classification in message schemas, policy-engine blocking of unauthorized cross-domain transfer, and PII masking before cross-boundary transmission.

**Agent swarm amplification attacks** (blast radius E): an attacker triggers exponential fanout — one agent dispatching to many sub-agents, each dispatching further — usable as DoS against target systems or to amplify a small injection into large-scale unauthorized action. Detect via fanout depth/breadth monitoring, rate limiting on agent-to-agent dispatch, and per-chain cost budgets. Prevent via a maximum fanout per agent (default 10), a maximum delegation chain depth (default 5), token-bucket rate limiting per originating agent, and orchestration-layer cost budgets.

**Infinite delegation loops** (blast radius D): Agent A delegates to B which delegates back to A (or via a longer cycle), entering infinite recursion without loop detection — causing resource exhaustion and cascading degradation. Detect via delegation chain cycle detection and a request depth counter in every call header. Prevent via delegation chain IDs carried in every request, rejection when an agent's own identity appears in the chain, and a maximum chain depth enforced independently of cycle detection.

**Registry compromise** (blast radius E): since discovery feeds every A2A call, compromising the registry — modifying cards, injecting malicious agents, or hiding legitimate ones — is systemic, causing enterprise-wide trust collapse. Detect via an immutable audit log on all registry writes, real-time alerting on unsigned card writes, and comparison against a content-addressed snapshot. Prevent via an append-only, content-addressed registry (IPFS-style or Merkle tree), multi-party approval for card changes, a published registry SPIFFE identity, and an out-of-band verification channel for critical agents. Recover via rollback to the last known-good signed snapshot, mass token revocation, and a full interaction-graph audit since the compromise window.

**Dependency supply-chain attacks** (blast radius E): malicious code in an agent's dependency (SDK, library, base model, container layer) executes with full agent privileges — the agent is legitimate, its code is not — with impact multiplied if the dependency is widely shared. Detect via SBOM-based dependency diff alerting, runtime behavioral baselining, and network egress anomaly detection. Prevent via an SLSA Level 3+ hermetic build pipeline, hash-verified dependency pinning, a private scanned artifact registry, and automated SBOM generation with vulnerability tracking.

**Insider threats** (blast radius E): an authorized developer or operator abuses legitimate access to register malicious agents, modify cards, extract credentials, or backdoor agent code — evading most controls since the credentials are legitimate. Detect via dual-approval workflows for sensitive operations, behavioral analytics on developer actions, and privileged access workstations for registry operations. Prevent via separation of duties (developer, registrar, and operator roles never combined in one person), just-in-time privileged access, mandatory MFA for sensitive operations, and code review requirements for capability changes.
