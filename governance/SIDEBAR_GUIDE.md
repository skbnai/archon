# Sidebar Authoring Standard

`sidebars.js` is the reader's map of the wiki. It must always match
`governance/TAXONOMY.md` exactly — the sidebar is not a separate decision, it
is that taxonomy rendered as navigation.

## Structure rules

1. **One top-level category per domain**, in this fixed order (matches
   TAXONOMY.md): Strategy & Operating Model → Architecture → Agentic Systems →
   Protocols & Interoperability → Data & Knowledge → Platforms & Infrastructure
   → Trust: Security, Governance & RAI → Operations & Economics → Learning
   Paths → Career & Skills → Asset Library.
2. **Curate, don't autogenerate**, for anything a reader will see. Every
   published category uses an explicit `items` array in deliberate reading
   order (foundational → practitioner → expert), not
   `{type: 'autogenerated', dirName: '...'}`. Autogenerated is acceptable only
   as a temporary staging view under `migration/` during a wave, never merged
   to a domain readers browse.
3. **Category anchors to the hub.** Every category sets
   `link: { type: 'doc', id: '<domain>/index' }` so clicking the category
   label itself opens the curated hub page — never a bare expandable folder
   with no content of its own.
4. **Reading order inside a category**: hub first, then foundational concepts,
   then guides/reference-architectures, then reference/checklist material
   last. Series (multi-part) stay contiguous and in numeric order.
5. **Nesting depth ≤ 2** inside a domain (domain → sub-category → doc). A
   third level is a sign the domain needs its own sub-hub instead.
6. **Collapsed by default**, `collapsible: true`, except the category matching
   the page currently open (Docusaurus handles this automatically via
   `sidebarCollapsed`/active-path expansion — don't hardcode per-category
   `collapsed: false`).
7. **Labels**: exact domain display name from TAXONOMY.md, Title Case, no
   emoji, no abbreviations a first-time reader wouldn't know (spell out "RAI"
   as "Trust: Security, Governance & RAI" once, then acronym is fine in
   sub-items).
8. **Every new page enters the sidebar in the same PR that adds the page.** A
   page that exists in `docs/` but not in `sidebars.js` is an orphan — the
   reviewer agent checks for this (cross-reference `docs/**/*.md` against the
   compiled sidebar doc-id list).

## Special sections

- **Learning Paths** and **Career & Skills**: flat lists, no sub-categories —
  these are already-curated journeys, further nesting adds friction.
- **Asset Library**: sub-categories by engagement phase (Discovery, Design,
  Delivery, Operate), not by file type.
- **ADR library** (`docs/architecture/adr/`): its own sub-category under
  Architecture, sorted by ADR number, newest last.

## Maintenance

Regenerate `docs/<domain>/_index.json` (graphify's `build_section_indexes.py`)
after any sidebar change so the machine-readable manifest and the human-facing
navigation never drift apart. `scripts/registry_check.py` should be extended,
where a project needs it, to also flag any registered canonical page missing
from the compiled sidebar doc-id list.
