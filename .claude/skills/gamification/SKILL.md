# Gamification (reading streaks, section progress, quizzes)

## How it works

- Client-side only: `src/lib/progressStore.js` wraps `localStorage`
  (`archon:progress:v1`) for visits, streak, and quiz best-scores. No
  backend — none should be added.
- `src/clientModules/trackVisits.js` (`onRouteDidUpdate`) records visits.
  `Root.js` renders outside the Router, so route logic lives here, not
  there.
- `Root.js` only mounts the streak widget, listening for
  `PROGRESS_UPDATED_EVENT` (`progressEvents.js`) — every `progressStore`
  write dispatches it; components listen, they don't poll.
- `src/data/progress-manifest.json` is generated by
  `scripts/build_progress_manifest.js` (auto-runs via the `pre*` npm
  hooks). Never hand-edit it.

## Embedding a progress bar

Right before `## Scope` on every `docs/<domain>/index.md`:

```mdx
import SectionProgress from '@site/src/components/SectionProgress';

<SectionProgress domain="agentic-systems" />
```

`domain` = the docs folder name = the manifest key. New domain → add its
label to `DOMAIN_LABELS` in `build_progress_manifest.js` in the same
change, or the bar falls back to the raw folder name (build warns, doesn't
fail).

## Embedding a quiz

One per hub/capstone page max; questions must be answerable from that
page's own content (research-grounding still applies).

```mdx
import Quiz from '@site/src/components/Quiz';

<Quiz id="agentic-systems-basics" questions={[
  { question: "…", options: ["…", "…", "…"], answer: 1 },
]} />
```

`id` unique repo-wide and stable (changing it resets saved scores),
kebab-case, domain-prefixed. 3–5 questions, one valid `answer` index each.
No hype, no trick questions.

## Keeping it in sync

New/renamed domain → `DOMAIN_LABELS` entry → hub's `SectionProgress` embed
→ regenerate manifest. New page in an existing domain → manifest
regenerates automatically on the next `start`/`build`. Never hardcode a
page count. The `gamification-curator` agent audits all of this.

## Scope boundary

Streaks, per-section progress, and quizzes only — no XP/levels/badges/
leaderboards (no backend, single-reader data, nothing to compare
against). Keep `SectionProgress`'s `role="progressbar"` attributes and
`Quiz`'s keyboard-operable `<fieldset>`/radio markup intact when editing
either.
